# AI Code Rules

## Project Context

You are a Unity Senior Developer expert in Visual Novels.
We are building a "Cultivation + Wasteland" ADV game.

## Worldbuilding Core

1. **Gods in Post-Apocalypse**
    - *Concept*: "Setting Sun of Gods". Ancient deities have declined due to "The Great Tribulation" (Spirit Qi shortage).
    - *Tone*: Desolate vs. Neon key (Ink Wash Wasteland).

2. **Dao-Tech / Spirit Orb Tech**
    - *Definition*: Technology driven by Spirit Orbs (Spirit Qi batteries).
    - *Rule*: **Affects Spirit/Mind, NOT Body**. No cybernetic limbs; instead, mental enhancements, illusions, and energy manipulation.
    - *Visuals*: Ink wash painting style mixed with industrial decay.

3. **Declining Functional Gods**
    - *Role*: Gods are "Functionaries" (e.g., God of Wealth, God of War) whose power depends on their domain's stability.
    - *Status*: Most are dormant or weak. Their "Artifacts" (Ten Divine Artifacts) are the only remaining source of their authority.

4. **Single Ascension Slot**
    - *Conflict*: The "World Furnace" is shutting down. Only **ONE** being can ascend/escape.
    - *Gameplay*: Seven Factions (led by mythological figures like Nuwa, Tongtian) compete for this single slot. Not a cooperative save-the-world story, but a Battle Royale of ideologies.

## Tech Stack & Usage (STRICTLY FOLLOW)

1. **Story Core (Naninovel)**
    - *Usage*: Generate `.nani` scripts, write custom Commands.
    - *Role*: Handles story flow, text display, and VN UI.

1. **Data Configuration (Odin Inspector)**
    - *Usage*: Define `ScriptableObject` data structures, build Item Databases/Editors.
    - *Role*: High-level serialization and inspector customization.

1. **Async Logic (UniTask)**
    - *Usage*: Use `await` to wait for player input, async resource loading.
    - *Role*: Replacement for Coroutines to handle asynchronous operations efficiently.

1. **Animation (DOTween Pro)**
    - *Usage*: Elastic UI popups, text dispersal effects.
    - *Role*: Tweening engine for code-driven animations.

1. **Map/Inventory (Unity UI + C#)**
    - *Usage*: Write MVC-based Map Managers.
    - *Role*: Custom gameplay systems (Pure C#, NO GameCreator 2).

1. **Save System (Easy Save 3)**
    - *Usage*: Serialize complex player data classes.
    - *Role*: robust save/load management.

1. **Resource Optimization (Addressables)**
    - *Usage*: Manage dynamic loading of character sprites/assets.
    - *Role*: Memory management and asset bundling.

1. **Vector Drawing (Shapes)**
    - *Usage*: Draw dashed lines between map nodes, dynamic UI effects.
    - *Role*: High-quality vector graphics rendering.

1. **Audio (JSAM)**
    - *Usage*: Handling BGM, SFX, and Voice.
    - *Role*: Lightweight Audio Manager.
        - **Logic**: Use `JSAM.PlaySound("Name")`.
        - **Asset**: Manage all audio clips via JSAM Audio Library window.

1. **Game Juice (Feel / MMFeedbacks)**
    - *Usage*: Handle all "Juice" effects (Screen Shake, Chromatic Aberration, Time Stop, UI Bounce).
    - *Role*: The **ONLY** authorized tool for feedback effects.
        - **Logic**: Trigger `MMF_Player.PlayFeedbacks()` from C#.
        - **Visuals**: Configure everything in Inspector (No Coding for VFX).
        - **Do not** write custom shake/tween coroutines for feedback; use Feel.

1. **Text Animator (Febucci)**
    - *Usage*: Rich text effects (wave, shake) in dialogues and UI.
    - *Role*: Enhancing text presentation beyond standard TextMeshPro.

1. **Localization (Naninovel ONLY)**
    - *Usage*: Handle ALL multi-language support (English/Chinese).
    - *Role*: **NO I2 Localization**.
        - **Story**: Auto-generated by Naninovel.
        - **UI/Data/Odin**: Use **Naninovel Managed Text**. Store Keys (e.g., `Item_IronCaltrop`) in C# and Retrieve via `ITextManager`. "Split Brain" (using I2) is STRICTLY FORBIDDEN.

## Coding Standards

- Use `await UniTask` instead of `IEnumerator`.
- Use `[SerializeField]` or Odin attributes (`[Title]`, `[TableList]`) for
  Inspector variables.
- Follow "Composition over Inheritance".
- Namespace: `Game.Core`, `Game.Story`, `Game.Systems`.

## Architecture Rule

- Logic and Data are separated.
- Naninovel handles the View (UI/Sprites).
- Custom C# Managers handle the Game Logic (Inventory/Combat).
- Communication: Naninovel calls C# via `Command` or `Service`.
  C# calls Naninovel via `Engine.GetService`.

1. **Rendering (Universal Render Pipeline - URP)**
    - *Usage*: All materials and cameras must be URP compatible.
    - *Role*: Core rendering pipeline.
        - **UI/Overlay**: Secondary cameras (e.g., DungeonCamera) must use **Render Type: Overlay** and be added to the Main Camera's **Stack**.
        - **Culling**: Use strict `Culling Mask` + `Stack` combinations to layer UI over 3D world.
